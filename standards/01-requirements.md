# 01 · 需求 / 活 PRD 〔本项目活记忆 · AI 维护〕

> **作用**:这是本项目唯一的需求文档。所有新功能、缺陷、技术债都追加到这里,不要另起多个 PRD 文件。
> **更新时机**:每次有新需求、需求变更、验收标准变化时更新。

---

## 1. 需求来源

| 类型 | 来源 | 进入方式 |
|---|---|---|
| 功能需求 Feature | 用户 / 老师 / 产品 / 客户 | 写成用户故事 |
| 缺陷 Bug | 测试 / 线上日志 / 用户反馈 | 写复现步骤和期望结果 |
| 技术债 Tech Debt | 开发 / Review / CI/CD 故障 | 写影响和修复目标 |

---

## 2. Issue 生命周期

| 阶段 | 状态 | 动作 |
|---|---|---|
| 提出 | Open | 写清场景、目标、验收标准 |
| 排期 | Backlog / Todo | 决定优先级和负责人 |
| 开发 | In Progress | 从 main 开 feature 分支 |
| 评审 | In Review | 提 PR,等待 CI 和 Review |
| 合并 | Done | PR 合并 main,自动关闭 Issue |
| 验收 | Verified | 按验收标准确认 |

**追踪规则**:分支名带 Issue 号,PR 描述写 `closes #<编号>`。

## 4. 需求清单

### US-1 初始化项目工程化与 CI/CD · 状态: Backlog

作为 **项目开发者**,
我想要 项目具备基础工程结构、测试、CI 与 CD,
以便 后续每次开发都能自动检查并自动部署。

验收标准:
- AC1: 从 `main` 开 feature 分支完成初始化,不直接 push main。
- AC2: PR 触发 CI,至少包含格式检查(ruff format)、静态检查(ruff check)、单元测试(pytest)、Docker 构建检查。
- AC3: CI 全绿后合并 main。
- AC4: 合并 main 自动触发 CD,部署后健康检查(HTTP 200 /health)通过。
- AC5: 完成后更新 `standards/PROGRESS.md`。

---

### US-2 银行营销数据交互分析页面 · 状态: Backlog

作为 **银行营销分析师**,
我想要 通过交互式页面查看银行营销数据的概要统计、单变量分布、双变量关系,
以便 快速理解客户特征与认购行为的关联。

验收标准:
- AC1: Given 应用已启动,When 访问首页,Then 显示数据集的概要信息(行数、列数、各字段类型)。
- AC2: When 点击「数据概览」页面,Then 以表格形式展示原始数据,支持分页浏览。
- AC3: When 进入「单变量分析」页面,Then 对数值字段显示直方图,对分类字段显示柱状图,图上有数据标签。
- AC4: When 进入「双变量分析」页面,Then 自由选择 X/Y 轴字段生成散点图或分组柱状图,支持按认购结果着色。
- AC5: When 在筛选面板选择特定年龄段/职业/婚姻状况,Then 所有图表和统计数据实时更新。
- AC6: When 所有页面加载,Then 图表渲染时间不超过 3 秒。
- AC7: Given 缺失数据,When 加载数据,Then 显示缺失值统计并提示用户。

技术备注:
- 使用 Streamlit 原生图表或 plotly 实现交互式图表。
- 数据在应用启动时从 `data/` 目录加载,若文件不存在则生成合成样本用于演示。

### US-3 离线训练分类预测模型 · 状态: Backlog

作为 **数据分析师/ML 工程师**,
我想要 一个离线训练脚本,基于历史营销数据训练二分类模型,
以便 在预测系统中加载并使用该模型判断客户是否会认购定期存款。

验收标准:
- AC1: 运行 `python model/train.py` 后,在 `model/saved_models/` 下输出一个序列化模型文件(`.joblib` 或 `.pkl`)。
- AC2: 训练脚本输出模型评估指标:AUC >= 0.80、F1 >= 0.60。
- AC3: 训练脚本默认生成特征列表文件(`model/saved_models/features.json`),记录训练所用特征名称与类型。
- AC4: 训练脚本对数值特征做标准化/归一化,对分类特征做编码,预处理流水线(Pipeline)随模型一起保存。
- AC5: 训练脚本输出特征重要性排序(树模型)或系数(逻辑回归)。
- AC6: 训练脚本可重复执行,相同数据产生相同结果(固定随机种子)。
- AC7: 当数据文件不存在时,训练脚本自动生成合成数据进行演示。

技术备注:
- 使用 scikit-learn Pipeline 确保预处理与模型一体化保存。
- 模型文件不进 Git(在 `.gitignore` 中排除 `model/saved_models/`)。

### US-4 在线认购预测系统 · 状态: Backlog

作为 **银行营销人员**,
我想要 在 Web 页面上通过点选表单输入客户信息(年龄、职业、婚姻状况、教育水平、上次接触结果等),
以便 实时获知该客户是否会认购定期存款以及认购概率。

验收标准:
- AC1: 当访问「在线预测」页面,Then 展示一个点选表单,包含数据集中所有关键特征字段的输入控件(下拉菜单、数字输入框、单选按钮等)。
- AC2: Given 已填写完整表单,When 点击「预测」按钮,Then 显示预测结果:「认购」或「不认购」及对应概率值。
- AC3: When 预测完成,Then 同时显示该客户与已认购/未认购客户群体的特征对比雷达图或条形图。
- AC4: Given 未选择任何字段,When 点击预测,Then 显示表单验证提示,不调用模型。
- AC5: Given 预测完成,When 变更表单输入并再次点击预测,Then 新结果在 2 秒内返回。
- AC6: When 模型文件不存在,Then 页面显示「模型未就绪」提示并引导用户运行训练脚本。
- AC7: When 页面加载且模型已就绪,Then 页面底部显示模型信息(训练时间、AUC、F1)。

技术备注:
- 预测时复用训练时保存的 Pipeline,确保输入预处理与训练时一致。
- 表单控件按特征类型动态生成(数值→slider/input,分类→selectbox)。

## 5. 非功能需求

- **安全**:密钥只进 Secrets,不进 Git。
- **可维护**:一需求一小 PR,避免大爆炸式提交。
- **可测试**:核心逻辑(数据处理、模型预测)必须有单元测试,覆盖率 >= 80%。
- **可部署**:Docker 容器化部署,容器内端口 8888,主机端口可回退(8888-8898)。
- **性能**:页面加载 < 3s,预测响应 < 2s。
- **鲁棒性**:数据/模型缺失时,应用不崩溃,显示友好提示或使用合成数据演示。
- **开源**:仓库公开,含 LICENSE 文件。
